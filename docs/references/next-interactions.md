# Next interaction mechanics: research handoff

Checked **2026-11-23** against official documentation, source licenses and the current repository. This records research before the second exploration slice. Packet travel and Boolean construction have since been implemented for review; see the [current capability guide](../technical/learning-engine.md). The other directions remain proposals. The accepted examples remain usable; homepage work stays deferred. No packages, datasets or paid services were invoked.

**Recommendation:** first add a reversible process traveler, then let learners build and test bounded Boolean networks. Both deepen the installed engine without another viewer. Treat deep zoom and molecular exploration as later, data-dependent slices: each library solves a real rendering problem, but neither supplies a scientifically meaningful lesson by itself.

## Four directions

| Direction | Concrete learner action and visible evidence | Reusable app primitive / library value | Prerequisites and boundary |
| --- | --- | --- | --- |
| **Process traveler** | Follow a packet between named hosts/routers; scrub backward to inspect its state before a forwarding event; change a scenario and compare delivery with a drop. | App-owned route, moving entity, event checkpoints, branch selection and deterministic state reconstruction. Existing SVG/React rendering is sufficient for the first schematic; no new library proposed. | Reviewed transition rules, authored topology/paths and trace fixtures. A schematic teaching model does not perform live network requests or simulate the whole Internet. |
| **Build and test logic** | Connect a supplied AND/OR/NOT palette to implement “exactly one input”; run all four combinations and inspect a counterexample, then repair the network. | Separate editable draft from validated executable graph; reuse the Boolean evaluator. Installed React Flow supplies connection editing and validation hooks, not the domain evaluator or learning feedback. [Validation](https://reactflow.dev/examples/interaction/validation), [computing flows](https://reactflow.dev/examples/interaction/computing-flows). | Typed input/output ports, bounded inventory and graph size, cycle/arity checks, target truth table. Ideal acyclic Boolean behavior remains the model; circuits with voltage, timing or memory need another reviewed evaluator. |
| **Scale transitions / microscope** | Move from a specimen overview to a labeled region, identify a structure at a useful scale and return to its context. | App-owned semantic levels, scale labels and explanatory transitions. OpenSeadragon adds on-demand tiled high-resolution image navigation and image-anchored overlays. [Tile sources](https://openseadragon.github.io/), [overlays](https://openseadragon.github.io/examples/ui-overlays/). | Licensed original with genuine detail, calibrated physical scale where claimed, regions and a tile pyramid or supported image service. Leaf → cell → organelle generally needs separately sourced views and explicit relationships; zooming a photograph cannot reveal uncaptured structures. |
| **Molecular structure** | Rotate a protein, select its ligand, focus the binding pocket and switch between whole-structure and local representations. | Mol* adds structure-aware molecular rendering; MolViewSpec (MVS) describes data, selections, representations, labels and camera/focus declaratively. This is substantial value beyond geometric GLB parts. [MVS functionality](https://molstar.org/mol-view-spec-docs/), [selectors](https://molstar.org/mol-view-spec-docs/selectors/). | Reviewed coordinate file, correct assembly/model, chain/residue identifiers and scientific explanation. A visualized structure or animated camera is not evidence of dynamics, binding affinity or a reaction mechanism. |

## 1. Process traveler: make state inspectable

Start with a small original network diagram and a registered **IPv6 forwarding teaching model**. A learner chooses an initial Hop Limit and one authored route scenario, predicts delivery, advances one event at a time and sees the packet's current location and remaining limit. IPv6 forwarders decrement Hop Limit by one and discard when it was received as zero or becomes zero; the destination has a distinct rule and should process a zero-limit packet normally. Preserve that distinction in fixtures and explanations. [RFC 8200 §3](https://www.rfc-editor.org/rfc/rfc8200.html#section-3).

Use two explicit branches initially: an ordinary route and a route with extra forwarding hops. Reconstruct `state = evaluate(initialState, scenarioId, checkpoint)` whenever the learner scrubs; do not replay destructive callbacks. Interpolate a token along a path for presentation between checkpoints, while discrete events own the model state. A scenario switch invalidates downstream checkpoints and returns to a clearly explained comparison point. If a later example adds a dropped packet followed by retry, label retry as a separate application/transport behavior with its own source and rule; IPv6 alone does not supply the retry lesson.

The present [ProcessStage](../../frontend/src/features/lesson/scenes/scene-stage.tsx) selects ordered titles/body text. Extend the capability contract with visible entities, checkpoint events and bounded branch conditions rather than merely animating that text. The same primitive could later support a photon path or algorithm trace, but each new domain still needs its own registered transition model and reviewed evidence.

## 2. Boolean builder: evaluate behavior, not matching wires

React Flow supports `isValidConnection` for proposed links; its official cycle example traverses outgoing nodes to reject a cycle. Use those capabilities for immediate feedback, then run the app's authoritative graph validator before evaluation. The library remains [MIT licensed](https://github.com/xyflow/xyflow/blob/main/LICENSE); these core examples do not require React Flow Pro. [Connection validation](https://reactflow.dev/examples/interaction/validation), [cycle example](https://reactflow.dev/examples/interaction/prevent-cycles).

Keep initial editing narrow: fixed input/output nodes, a small authored gate palette, add/remove connections and Reset. Provide “connect source → destination input” native selects/buttons as an alternative to dragging; moving node positions is optional. Once the network is executable, enumerate the full input combinations for this small problem and compare its output with the target truth table. Accept functionally equivalent solutions; return a specific failing input combination rather than demand one reference wiring.

The current [systemSchema](../../frontend/src/features/lesson/contracts/scene.ts) requires valid gate arity and an acyclic complete graph. Keep that executable contract. Add a distinct bounded draft representation whose result is `incomplete`, `invalid` or `ready`; a missing connection must never silently become Boolean false. Preserve the last verified result only with an explicit stale indication, or clear it after editing. This requires authored success conditions and app-owned feedback, not generated evaluator code.

## 3. Deep zoom: gate installation on real image detail

OpenSeadragon supports DZI and IIIF tile sources; its IIIF integration requires CORS support for cross-origin image-server access. Its preparation guide describes converting large originals into tiled zooming formats, including local conversion tools. A local DZI pyramid is compatible with the app's prepared-data approach; an external IIIF service adds a runtime availability dependency. [Preparation](https://openseadragon.github.io/examples/creating-zooming-images/), [IIIF integration](https://openseadragon.github.io/examples/tilesource-iiif/).

Its [New BSD / three-clause license](https://github.com/openseadragon/openseadragon/blob/master/LICENSE.txt) permits redistribution with notice and non-endorsement conditions; image rights are separate. Require a source/rights record, dimensions, a verified physical calibration if shown, tile availability and annotated regions before choosing it. For modest images already served whole, the installed pan/zoom capability is enough. For meaningful cross-scale travel, store level-specific units, what each view actually depicts, and whether its link to the previous view is measured, representative or schematic. Never present unrelated specimens as one continuous photographed zoom.

## 4. Molecular viewer: curate a structure packet first

Use a small experimentally determined structure with a ligand as the first candidate. Supply a pinned local mmCIF or BinaryCIF resource, entry/version, biological assembly or explicit model choice, selected chain/residue IDs, ligand identity, credit, primary citation and qualifications about the experimental model. The MVS tree schema explicitly distinguishes model/assembly/symmetry structures and supports targeted components; verify every selected ID against the supplied file. [Tree schema](https://molstar.org/mol-view-spec-docs/tree-schema/). PDB archive files are [CC0](https://www.wwpdb.org/about/usage-policies), with attribution encouraged; do not assume that adjacent article figures or other databases have identical terms.

Both [Mol*](https://github.com/molstar/molstar/blob/master/LICENSE) and [MolViewSpec](https://github.com/molstar/mol-view-spec/blob/master/LICENSE) use MIT licenses. Prefer a lazy client-side Mol* adapter that loads validated MVS JSON from prepared assets; official examples support loading/replacing MVS views. MVSX can bundle the scene, coordinates and annotation files together, avoiding hidden external downloads. [Integration](https://molstar.org/mol-view-spec-docs/mvs-molstar-extension/integration/), [encodings](https://molstar.org/mol-view-spec-docs/#encoding).

Do not adopt MolViewStories' code editor as the lesson execution model. The useful seam is a reviewed subset of MVS data. Snapshots can sequence molecular views, but interpolation is a presentation capability; real conformational trajectories require supplied coordinate frames, provenance and separate scientific review. [MVS animations](https://molstar.org/mol-view-spec-docs/animations/). Mobile rendering, memory limits and fallback views need an actual representative asset test before accepting this viewer.

## Ordered next slice and authoring contract

1. **One packet traveler:** implement checkpoint navigation, reversible scrubbing, two route scenarios and an adjacent state explanation. Acceptance: changing Hop Limit can change delivery/drop; reversing and returning to a checkpoint produces identical state; no live requests occur; keyboard and reduced-motion operation expose the same evidence.
2. **One Boolean construction task:** add bounded editing, explicit draft diagnostics and exhaustive truth-table testing. Acceptance: a correct alternative wiring passes, a near miss produces a counterexample, and incomplete/cyclic graphs never yield a fabricated output. Verify narrow mobile use with native connection controls.
3. **One asset feasibility gate:** acquire and review either a calibrated tiled specimen or a molecular structure packet, then compare actual learning value and mobile cost against the existing viewer. Only then propose a library addition. Do not make both integrations prerequisites for the first two tasks.

Agents should emit prepared JSON through these contracts; application code owns transitions, calculations and adapters:

| Contract | Required authored data | Validation before rendering |
| --- | --- | --- |
| Shared | Capability/model version, learning objective, learner action, observable evidence, assumptions, source indices, complete reading and fallback description | Strict schema, bounded size/ranges, source references, capability compatibility and factual review |
| Traveler | Entity/location IDs, topology, registered model ID, bounded initial parameters, scenario IDs, checkpoint/event IDs and explanations | References/reachability, finite traces, valid model parameters, expected trace fixtures; no arbitrary predicates or expressions |
| Builder | Registered gate kinds, allowed inventory/ports, initial draft, input/output IDs, target truth table and hint explanations | Unique IDs, port/type/reference limits, full target coverage, draft diagnostics; compile only ready graphs to the executable schema |
| Scale / molecule | Approved local asset IDs, source/rights metadata, reviewed regions or structure selectors, named views and units where applicable | Asset availability, dimensions/calibration or selector existence, bounded resource use and permitted adapter options |

Persistence needs an explicit decision: [useLearningState](../../frontend/src/features/lesson/shared/session.tsx) and the [guest-state schema](../../frontend/src/state/guest/schema.ts) currently accept flat records of numbers, booleans, short strings and bounded numeric arrays. Nested graph drafts cannot be silently cast or packed into unchecked JSON strings. Add a typed, versioned state variant or use a genuinely bounded validated ID representation. Persist user choices/drafts and checkpoint position, never active playback; Reset and incompatible-version fallback must remain predictable.

**Verification boundary:** primary-source capabilities/licenses and the repository seams above were inspected. No viewer was installed, no dataset downloaded, and no browser/performance/accessibility behavior was tested. The acceptance checks above are proposed work, not passed evidence.
